# V100 GPU 适配方案：ClarQ GRPO 训练

## 问题诊断

V100 GPU（Volta 架构，compute capability 7.0）在运行当前 ClarQ 训练流程时面临：

1. **FlashAttention 2 不兼容**：FA2 需要 Ampere 及以上架构（A100/A6000/RTX 30/40系列），V100 不支持
2. **vLLM v1 AsyncLLM 限制**：最新 vLLM v1 引擎对老架构优化较少，可能有兼容性问题
3. **显存限制**：V100 典型配置 16GB，Qwen3-4B + vLLM rollout 的显存占用可能吃紧
4. **多轮 Agent 推理需求**：当前依赖 vLLM 的 async 模式做 tool calling

## 方案对比（按推荐优先级排序）

| 方案 | 优点 | 缺点 | 难度 |
| --- | --- | --- | --- |
| **1. 使用 SGLang 替换 vLLM** | 对老架构友好，支持 V100，性能接近 vLLM | 需改配置，可能需微调 multi-turn 参数 | ⭐⭐ |
| **2. 降级 vLLM 到 0.3.x/0.4.x** | 官方支持 V100，稳定 | 缺少新特性，需禁用部分新功能 | ⭐⭐⭐ |
| **3. 使用 HFRollout（Transformers 原生）** | 最通用，无架构限制 | 慢，不支持 paged attention，显存效率低 | ⭐ |
| **4. 量化 + 更小模型** | 降低显存压力 | 可能影响性能，Agent RL 对模型能力敏感 | ⭐⭐⭐ |
| **5. 混合方案：vLLM(训练) + API(模拟器)** | 分离模拟器到其他机器 | 需要额外硬件资源 | ⭐⭐ |

---

## 方案 1：使用 SGLang（推荐✅）

**SGLang** 是字节跳动开源的推理引擎，专注于结构化输出和多轮对话，对 V100
支持良好，VeRL 原生支持。

### 1.1 安装 SGLang（替换 vLLM）

```bash
# 在你的环境中
pip uninstall vllm -y

# 安装 SGLang（支持 V100 的版本）
pip install "sglang[all]==0.3.7.post2"

# 验证
python -c "import sglang; print(sglang.__version__)"
```

### 1.2 修改训练脚本

编辑 `examples/clarq_grpo/run_qwen3_4b_grpo.sh`，在 `python3 -m verl.trainer.main_ppo` 命令中：

**原配置（第 111-112 行）：**
```bash
actor_rollout_ref.rollout.name=vllm \
actor_rollout_ref.rollout.mode=async \
```

**改为：**
```bash
actor_rollout_ref.rollout.name=sglang \
actor_rollout_ref.rollout.mode=async \
```

### 1.3 调整 SGLang 特定参数

在训练脚本的 rollout 配置块添加：

```bash
actor_rollout_ref.rollout.engine_kwargs.sglang.attention_backend=triton \
actor_rollout_ref.rollout.enforce_eager=True \
```

- `attention_backend=triton`：V100 用 Triton kernel 替代 FlashAttention
- `enforce_eager=True`：禁用 CUDA graph（V100 的 graph 支持不如 Ampere）

### 1.4 启动独立的 SGLang 模拟器服务

**停止原来的 vLLM 模拟器**，启动 SGLang 版本：

```bash
# GPU 0 运行 Qwen3-32B 用户模拟器
CUDA_VISIBLE_DEVICES=0 \
python -m sglang.launch_server \
  --model-path /data/pretrained_models/Qwen3-32B \
  --host 127.0.0.1 \
  --port 8005 \
  --tp 1 \
  --mem-fraction-static 0.88 \
  --disable-flashinfer \
  --context-length 8192

# GPU 1 运行 embedding（仍用 vLLM，或者换成 sentence-transformers，见下文）
```

### 1.5 Embedding 服务替代方案

如果 vLLM embedding 也有问题，可用 `sentence-transformers` 起 FastAPI 服务：

```bash
pip install sentence-transformers fastapi uvicorn
```

创建 `embedding_server.py`：

```python
from fastapi import FastAPI
from sentence_transformers import SentenceTransformer
import uvicorn

app = FastAPI()
model = SentenceTransformer("/data/pretrained_models/BAAI-bge-large-en-v1.5")

@app.post("/v1/embeddings")
async def embed(request: dict):
    texts = request["input"]
    embeddings = model.encode(texts, normalize_embeddings=True)
    return {
        "data": [
            {"index": i, "embedding": emb.tolist()}
            for i, emb in enumerate(embeddings)
        ]
    }

if __name__ == "__main__":
    uvicorn.run(app, host="127.0.0.1", port=8001)
```

启动：
```bash
CUDA_VISIBLE_DEVICES=1 python embedding_server.py
```

## 方案 2：降级 vLLM 到 0.3.x/0.4.x

老版本 vLLM 官方支持 V100，但缺少新版的 multi-turn / tool calling 优化。

### 2.1 安装 vLLM 0.4.3（V100 最后稳定版）

```bash
pip uninstall vllm -y
pip install vllm==0.4.3
pip install flash-attn==2.0.0  # V100 兼容版本，实际会 fallback 到非 FA 实现
```

### 2.2 禁用不兼容特性

修改 `run_qwen3_4b_grpo.sh`：

```bash
actor_rollout_ref.rollout.name=vllm \
actor_rollout_ref.rollout.enforce_eager=True \
actor_rollout_ref.rollout.free_cache_engine=False \
actor_rollout_ref.rollout.gpu_memory_utilization=0.85 \
```

- 禁用 `free_cache_engine`（新版特性）
- `enforce_eager=True`：强制 eager 模式
- 降低显存利用率避免 OOM

### 2.3 处理 AsyncLLM 缺失问题

如果 vLLM 0.4.x 没有 `AsyncLLM`，需要改用**同步模式**：

```bash
actor_rollout_ref.rollout.mode=sync \
```

但这会牺牲一部分并发效率。

## 方案 3：使用 HFRollout（纯 Transformers）

不依赖任何推理引擎，但速度慢且显存效率低，**仅作为最后保底方案**。

### 3.1 修改训练脚本

```bash
actor_rollout_ref.rollout.name=hf \
actor_rollout_ref.rollout.mode=sync \
actor_rollout_ref.rollout.micro_batch_size=1 \
```

### 3.2 限制

- 不支持 paged attention，长对话容易 OOM
- 无法用于生产环境的 Agent RL
- 建议只用于**验证流程能否跑通**，不适合实际训练

## 方案 4：量化 + 更小模型

### 4.1 模型选择

| 原模型 | V100 友好替代 | 备注 |
| --- | --- | --- |
| Qwen3-4B | Qwen2.5-3B | 更小，性能接近 |
| Qwen3-32B（模拟器） | Qwen2.5-14B + INT8 | 或远程 API |

### 4.2 量化配置（bitsandbytes）

```bash
pip install bitsandbytes

# 在 agent.py 的 UserSimulatorClient 中改用量化模型
# 或在训练脚本中添加：
actor_rollout_ref.model.load_in_8bit=True
```

### 4.3 风险

- Agent RL 对模型推理能力敏感，量化可能降低 clarify 和 search 质量
- 需要重新调整 reward 权重

---

## 方案 5：混合部署（推荐用于多机环境）

将 Qwen3-32B 模拟器和 embedding 放到**另一台有 A100/V100 的机器**或**云 API**：

### 5.1 模拟器改用 OpenAI API

如果有 OpenAI/Anthropic/Aliyun 等 API 额度，修改 `agent.py` 中的
`UserSimulatorClient.base_url` 为远程地址，使用真实 API：

```python
# agent.py:72
self.base_url = "https://api.openai.com/v1"  # 或其他兼容 OpenAI 格式的 API
self.model = "gpt-4o-mini"  # 便宜且够用
self.api_key = "sk-..."
```

### 5.2 训练机器只跑 Qwen3-4B

在 V100 机器上只运行策略模型训练，不再本地起模拟器和 embedding：

```bash
# V100 机器：只训练
export USER_SIMULATOR_BASE_URL=http://<远程机器IP>:8005/v1
export EMBEDDING_URL=http://<远程机器IP>:8001/v1/embeddings

TRAIN_CUDA_VISIBLE_DEVICES=0,1 bash examples/clarq_grpo/run_qwen3_4b_grpo.sh
```

## 显存优化通用配置（适用所有方案）

无论选哪个方案，都建议添加以下配置到训练脚本：

```bash
# 降低 rollout 显存占用
actor_rollout_ref.rollout.gpu_memory_utilization=0.75 \
actor_rollout_ref.rollout.max_num_seqs=4 \
actor_rollout_ref.rollout.max_model_len=6144 \

# 启用 gradient checkpointing
actor_rollout_ref.model.enable_gradient_checkpointing=True \

# 降低 batch size
TRAIN_BATCH_SIZE=1 \
PPO_MINI_BATCH_SIZE=1 \
ROLLOUT_N=2 \

# 启用 CPU offload（牺牲速度换显存）
actor_rollout_ref.actor.fsdp_config.param_offload=True \
actor_rollout_ref.actor.fsdp_config.optimizer_offload=True \
```

## 推荐实施路径（按优先级）

### 第一步：快速验证（1 小时）
1. 尝试**方案 1（SGLang）**，安装后直接替换 `rollout.name=sglang`
2. 用 `smoke` 模式跑 1 个 step：
   ```bash
   scripts/clarq_pipeline_4gpu.sh smoke
   ```
3. 如果成功，继续用 SGLang 完整训练

### 第二步：如果 SGLang 有问题（2 小时）
1. 尝试**方案 2（vLLM 0.4.3）** + 显存优化配置
2. 同样先 `smoke` 测试

### 第三步：如果仍失败（半天）
1. 评估是否可以**方案 5（混合部署）**，把模拟器放到其他机器或用 API
2. 如果资源受限，只能**方案 3（HFRollout）** 保底，但需接受速度慢

### 长期方案
- 如果 V100 无法满足训练需求，建议：
  1. 云上租 A100（按小时计费，训练完就释放）
  2. 或使用 Qwen2.5-3B 等更小模型 + V100
  3. 或等待 SGLang/vLLM 对老架构的进一步优化

## 常见报错与解决

| 错误信息 | 原因 | 解决 |
| --- | --- | --- |
| `CUDA error: no kernel image is available` | Flash-Attn 2 不支持 V100 | 设置 `enforce_eager=True` 或换 SGLang |
| `OutOfMemoryError` in rollout | vLLM 显存占用过高 | 降低 `gpu_memory_utilization`、`max_num_seqs` |
| `AsyncLLM not found` | vLLM 版本太老 | 用 `rollout.mode=sync` 或升级到 0.4.3+ |
| `Tool calling format error` | 多轮格式不兼容 | 检查 `multi_turn.format=hermes` 是否与模型 tokenizer 匹配 |
| Training OOM on actor update | FSDP 显存不足 | 启用 `param_offload=True` + 降低 batch size |
