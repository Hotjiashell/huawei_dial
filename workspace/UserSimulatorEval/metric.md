# 用户模拟器评估指标
很多用户模拟器研究并不设计指标来说明他们的评估器像人，而是直接列出人在对话中会表现出的非配合特性（比如突然聊无关话题、对澄清问题的无效回答、不耐烦），然后让用户模拟器表现出这些特性，再测试客服Agent发现其性能下降，来说明现有用户模拟器确实不像人。

如果要用指标说明用户模拟器像人，或许可以引入一些人类真实数据，来和人类真实数据的统计结果做对比来说明UserSimulator的效果。华为数据有真实对话数据，但ClarQ就没有了。

# 指标
可能都只能用LLM Judge来看，针对我们的场景，可能比较有必要的是：
- 信息提供效率：用户每次针对澄清，回复的信息点数量是否过多
- 信息泄漏率：是否透漏了客服并未准确追问的信息点

（不确定是否考虑，考虑了可能会引入太多复杂性：
- 无关内容：比如询问修电脑时，说起自己某某工作很忙，明天就要交付
- 无效回答：对澄清问题的回答没有回答到点上
- 情绪化：出现愤怒、不耐烦等语言
）
